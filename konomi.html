Built with Konomi.

Konomi is a living-system architecture created by Thomas Frumkin. Everything on this estate is what we've built with it — sovereign software you own, running on your own machines. Konomi itself lives at its own home; this page is only the proof of what one person built on it.

The four promises

1 · You own it

A Konomi tool is a file, not a subscription. The source is in your hands under a licence nobody can revoke. There is no vendor who can raise the price, discontinue the product, or switch it off — because there is no vendor between you and your software.

Proof: the estate — hundreds of live builds, every one open-source, every one a page that keeps working if we disappear tomorrow.

2 · It runs on your machines

Konomi software runs in your browser and works offline. Your client records, case files, and numbers stay on your device — they never travel to a server, because there is no server. For firms whose regulators expect them to control client data, this isn't a preference; it's the point.

Proof: the regulated shelf — working tools for claims firms, accountants, brokers, and agents, each one running entirely on the machine that opens it.

3 · The maths is proven before it ships

The engines that compute deadlines, totals, and money are tested by deliberately breaking them — mutation testing — which checks not just that the code passes its tests, but that the tests would catch the code if it were wrong. A total that can't reconcile refuses the document instead of being silently absorbed. And where an engine has a limit, the limit is printed on the page.

Proof: Northgate Claims — a fictional firm running a live working day on those engines, with its own limitations stated on screen.

4 · Machines never cross the human doors

In a Konomi system, automated agents run the routine work — but four kinds of action always stop and wait for a named person: moving money, signing anything legal, judgment calls, and moments of client trust. This is enforced in the software itself, not written in a policy. Nothing signs itself.

Proof: the konomified company — a 100-person firm designed seat by seat, where the org chart is validated by code that refuses any structure breaking that rule.

What Konomi does not do — yet

Said plainly, because trust is the product:

Konomi tools today are single-device by design — there is no shared multi-user layer, so a team working one caseload together needs that layer built as part of their deployment. There is no cloud scale-out, because there is no cloud. And a Konomi system will not pretend to be finished: every demo prints its current limits, and this page will keep this section for as long as it stays true. A vendor that hides where it's weak shouldn't be trusted where it's strong — that rule applies to us first.
