Built with Konomi.

Konomi is a living-system architecture created by Thomas Frumkin. Everything here is what we built with it: software you own, running on your own machines. What I have built is one small part of what Konomi can do. It is a fork, downstream of Thomas. Konomi has its own home. This page is only the proof of what one person made on a corner of it.

What every build here keeps

1 · You own it

Every build here is a file, not a subscription. You hold the source code, under a licence no one can take back. No seller can raise the price, stop the product or switch it off. There is no seller between you and your software.

Proof: all we built. Hundreds of live builds. Each one is open code. Each one is a page that keeps working if we are gone tomorrow.

2 · It runs on your machines

These builds run in your browser, and they work with the network off. Your client records, case files and numbers stay on your device. They never go to a server, because there is no server. Some firms must keep control of client data by law. For them this is the whole point.

Proof: the regulated shelf. Working tools for claims firms, accountants, brokers and agents. Each one runs fully on the machine that opens it.

3 · The maths is proven before it ships

The parts that work out deadlines, totals and money are tested by breaking them on purpose. That checks more than whether the code passes its tests. It checks that the tests would catch the code if it were wrong. A total that does not add up is refused. It is not quietly let through. And where a part has a limit, the limit is printed on the page.

Proof: Northgate Claims. A made-up firm running a live working day on those parts, with its own limits shown on screen.

4 · Machines never cross the human doors

In the systems I build on Konomi, AI workers do the everyday work. But four kinds of action always stop and wait for a named person. They are moving money, signing anything legal, judgement calls, and moments of client trust. The software itself enforces this. It is not just written in a rule book. Nothing signs itself.

Proof: the AI-first company. A firm of 100 people, planned seat by seat. Code checks the staff chart, and refuses any plan that breaks that rule.

What these builds don't do — yet

Said plainly, because trust is the product:

Today these builds are made for one device. There is no shared layer for many users. So a team working one caseload together needs that layer built as part of their set-up. There is no cloud to grow into, because there is no cloud. And a build here will not pretend to be finished. Every demo prints its limits, and this page keeps this part for as long as it stays true. A seller that hides where it is weak should not be trusted where it is strong. That rule applies to us first.
